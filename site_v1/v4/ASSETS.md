# V4 assets: replacing photographic layers

Every photographic layer on the V4 homepage is set in **one file**:
`site_v1/v4/assets/js/v4-assets.js` (`window.V4_ASSETS`). The layout, the animation and the markup all
read from it. To replace an asset you change that file. You do not touch the CSS, `scenes.js` or the HTML.

## 1. Hero cars (Alex's final cut-outs)

Each car is a group `.car.car--{ferrari|ford|porsche}` with two layers:

| layer | today | source |
|---|---|---|
| `body` | `assets/img/hero/{ford-gt,p911-green,f458-speciale}_body.webp`: the opaque car (alpha ≥ 250), cropped to the car | `HERO VIDEO SCRAB'/{1,2,3}_1.png` (Ford GT · 911 · 458 Speciale), received 2026-10-09 |
| `shadow` | `assets/img/hero/*_shadow.webp`: everything else in the same PNG (soft ground shadow + edge anti-aliasing) | same file, same pixel grid; body over shadow recomposes the PNG exactly |

The split is made by alpha: body = pixels with alpha ≥ 250, shadow = the rest. Anchor = body bbox centre-x, contact line = the body's lowest row.

**Positioning uses an anchor, never source scale.**

- `body.anchor` is a point in the body file's own pixels: **bbox centre-x, contact line** (tyre contact, or the splitter lip where the tyres are hidden).
- `shadow.anchor` is the shadow pixel that sits exactly under `body.anchor`.
- `shadow.scale` is shadow pixels per body pixel: 1 if both files come from the same master, 0.5 if the shadow is exported at half resolution.
- `frames.F1/F2/F3/EXIT/M1` store `[anchor-x, anchor-y, W]` in stage units: a 1920×1080 stage on desktop and a 390-wide stage on mobile (M1). `W` is the rendered body width.

### Drop-in procedure

1. Put the files in `site_v1/v4/assets/img/hero/`.
2. In `v4-assets.js`, edit `cars.<name>.body` (`src`, `w`, `h`, `anchor`) and `cars.<name>.shadow` (`src`, `w`, `h`, `anchor`, `scale`).
   - Set `blend` to `"normal"` for an alpha shadow, or `"multiply"` only for a white-ground plate.
3. Reload. The runtime (`assets/js/cars.js`) re-positions everything from the file.
4. Optional: refresh the no-JS fallback markup with `python -I site_v1/v4/_build/gen.py`. The JSON block in `v4-assets.js` must stay strict JSON.

**Resolution targets** (from STORYBOARD.md §4), as body width at 2× the largest W:

- Ford ≥ 2310 px
- Ferrari ≥ 2060 px
- Porsche ≥ 1870 px

At 1x every layer is ≤ 1:1 today. On DPR-2 screens the temp files upsample until the finals arrive.

**The Wake lock** survives a swap. The Collection photo P1 rides 36 stage-px below the Ford's shadow tail, and that tail is computed from `shadow.h − shadow.anchor[1]` (`V4.cars.shadowTail`). A new shadow of a different length keeps the lock.

## 3. Rules that bind any replacement

- Real duPont REGISTRY photography only. No generated imagery and no paid services.
- Each listing photo's real listing ID goes in `listing`.
- Photos stay sharp, unaltered rectangles. No blur, feather, vignette or fake light.
- Keep every layer ≤ 1:1 at the 1920 stage. Growth ends in a crop or an exit, never an upscale past 1.00.
